## [Unreleased]

### Argus takes over: a trustworthy orchestrator with visible work

The orchestrator formerly known as Jarvis is now **Argus**, running Hermes-first with failover, and every task finally leaves a paper trail: a working directory you can open in Finder, a recorded file list, and a run history on the task card.

### Added
- **Repeated-problem signal mining dispatch nudges** — requests that decide what to build, ship, or prioritize next (a roadmap, a backlog item, "which feature", "what should we build next") now get a deterministic repeated-problem signal-mining check before dispatch unless the operator already framed the roadmap as a repeated-problem signal. The agent must name the field/community surface and the reporters, rank the problems reported repeatedly with the most-repeated one first, state the top repeated problem as the concrete requirement the next build answers, name the proof/case artifacts that evidence it, map the demand path (funnel) and the talent path, pick the smallest next step that answers the top problem and say whether demonstrated demand now needs distribution rather than more building, and give a verdict — repeated-problem-sourced versus invented-feature (no repeated signal behind it — defer or validate first). Applies Jake Van Clief's Adoba pattern (video `ENQgYWikm2Q`): the community surfaced the same problems "over and over and over again" and those repeated complaints became the product thesis rather than an invented roadmap, so the most-repeated problem *is* the requirement. `src/repeated-problem-signal-mining.js` holds the deterministic gate; the prose guide lives in `docs/REPEATED-PROBLEM-SIGNAL-MINING.md`. Distinct from opportunity-routing (route a market/client workflow to paid pain that already moves money), question-discovery (extract the right question from an underdefined task), and cross-domain-adjacency (borrow an idea from an adjacent field).
- **Capability-assumption review dispatch nudges** — requests whose plan rests on a claim that the AI/model/tool cannot do something ("the model can't handle long documents", "AI isn't reliable enough for legal review so we keep a human in the loop", "LLMs can't do math, we'll compute it in a script", "agents still hallucinate so we double-check everything") now get a deterministic capability-assumption check before dispatch unless the operator already framed the claim as dated and re-testable. The agent must name the assumption (which model/provider/tool, which capability, and the capability level the claim was defensible at), treat it as a dated tactic that may have expired as capability ratcheted, separate the durable workflow goal from the dated tactic, attach an explicit re-test trigger (a model release, a provider change, or a prompt/context change), re-test cheaply against the current model (a small representative probe or a shadow task on the newer model) before keeping the workaround, state what would have to be true for the assumption to flip and where the dated claim is recorded so a future run can re-open it, and give a verdict — capability-assumption-held versus stale/re-test. Applies Jake Van Clief's capability short ("If you want to work for me. Try my community.", video `iWpJr2A2GRc`): a "language models are useless" claim was defensible at a GPT-3 capability level and simply expired as capability improved, so a capability claim is a dated tactic, not a permanent fact. `src/capability-assumption-review.js` holds the deterministic gate; this nudge makes the operator's agents run it at dispatch time. Distinct from spec-before-the-machine (write the capability spec despite tooling parity), workflow-resilience (outage/quota/provider degradation), runtime-reach-portability (whether a runtime has the reach a job needs), and baseline-ratchet (raising the challenge as the floor rises).
- **Position-addressed memory dispatch nudges** — requests that design how an AI remembers or retrieves context for a workflow ("build the knowledge base", "should we add a vector database", "let the agent remember across sessions", "how should we organize memory", "set up a second brain") now get a deterministic address-mode check before dispatch unless the operator already named the address mode and its layout. The agent must name the memory address mode the job needs — position-addressed (folders/paths/filenames/cascading instructions/templates/local routing files carry the meaning), link-addressed (wiki/entity graph/maintained notes followed by explicit links), or content-addressed (embeddings/vector/semantic search) — prefer position-addressed first as the cheapest, human-inspectable, provider-portable layer, avoid building embeddings before the workflow has a stable folder/process shape, lay out the workbench (front desk, canonical manifest, cascading context, templates, source-vs-derived separation, review surface, portability constraint), keep human-legible paths and an index for fresh-session continuity, and give a verdict naming the chosen address mode and the folder/routing structure. Applies Jake Van Clief's position-addressed-memory lesson (concept `position-addressed-memory`; video `hALln9wrrQo`): location itself carries meaning, so a path like `projects/client/scene-03.md` tells the model and human the client, deliverable, stage, and conventions before the file body is read. `src/position-addressed-memory.js` holds the deterministic gate; this nudge makes the operator's agents run it at dispatch time. Distinct from scoped-memory-routing (where a single preference is stored), context-boundary (what context crosses a boundary), company-brain (org-scoped navigable knowledge), and continuity-workbench (resuming one workflow).
- **Interface-layer selection dispatch nudges** — requests that propose choosing or standing up an AI tool/interface to do a job ("use Claude to browse…", "build an agent", "connect it to our API", "set up a terminal workflow", "which model should we use", "spin up a custom orchestration") now get a deterministic interface-layer check before dispatch unless the operator already named the layer and its access need. The agent must name the access the job actually needs the layer to provide (see → web/URL/connector; edit → files/repo; run → commands/tests; persist → durable state; expose → API/webhook/secret/collaboration), recommend the simplest sufficient layer (plain chat/desktop for ideation; a file/IDE agent for repo edits and tests; a terminal/CLI agent for batch file and command work; a deterministic script for repeatable transforms; hosted co-work only for a managed-workspace need; a custom orchestration/multi-agent runtime only when no simpler layer can satisfy permissions, scaling, audit, isolation, or integration), route durable state out of chat into files (manifest, notes/CLAUDE.md, index, PRD, tests, commits, runbook), separate public artifacts from private context and secrets, put evolving artifacts under git, and give a verdict naming the chosen layer, the access need, and what stays a human judgment point. Applies Jake Van Clief's interface-layer lesson (videos `rHDA0WMXzy4`, `0fCQ-4J_jzk`, `ozkx_eUfjY0`): choose a tool by the access layer the job needs, not by brand, hype, or "agent" language, and prefer the simplest layer that can complete and verify the job. Distinct from runtime-reach-portability (reach/vendor-independence once a runtime is already named), automation-timing (whether and how far to automate a step), workflow-resilience (provider outage/quota/degradation), and source-runtime-value (source-code/import work). `src/interface-layer-selection.js` holds the deterministic gate; this nudge makes the operator's agents actually run it at dispatch time.
- **Automation-timing dispatch nudges** — requests that propose making a step automatic ("add an agent", "set up a cron", "automate the reporting step", "wire up an integration", "build a workflow") now get a deterministic automation-timing check before dispatch unless the operator already supplied an escalation frame. The agent must place the step on Visionary's escalation ladder (manual note → copy/paste assist → deterministic helper → one-shot agent dispatch → scheduled automation → productized integration), recommend the cheapest sufficient level (a script before an agent and a reviewable task before an autonomous cron; no agentic loop until simpler methods fail), name the retained human checkpoint where judgment, accountability, or domain risk lives, state the promotion evidence (trigger, input/secret boundaries, failure handling, review surface, reversibility, fresh-session proof), name the demotion trigger, and give a verdict naming the target level and the retained checkpoint. Applies Jake Van Clief's "The Real Skill in AI: Knowing What Not to Automate" lesson (`ZMDXs59Ntjc`) and wires the existing prose rubric (`docs/AUTOMATION-TIMING-RUBRIC.md`) into dispatch time. Escalation-timing layer, distinct from augment-over-automate (the riderless posture once automation is chosen), ai-workflow-ladder (learning/promotion framing), workflow-capture (the written procedure for a repeated job), and workflow-resilience (outage/quota/degradation).
- **Persistent multi-session chat** — Argus conversations are stored in SQLite (`chat_sessions`/`chat_messages`, migration 10) and survive restarts; the panel gains a session switcher + new-chat button; the last 12 turns replay into every prompt so context follows across harness failovers. Session CRUD at `/api/chat/sessions`.
- **Interface-boundary dispatch nudges** — API/CLI/tool/webhook/route/schema/adapter/integration requests now get a deterministic contract check when boundary or verification signals are present: exact surface, inputs/outputs, secret scope, read-back/smoke/schema verification, and failure behavior.
- **Collaborative-document branch dispatch nudges** — requests that put more than one agent/person/role onto a shared document/spec/file, or branch/merge/version a durable artifact, now get a deterministic artifact-centered check: source discussion vs. active artifact, bounded edit contracts per agent, section/chunk targeting, a version/diff ledger, branch/parent links, and an explicit accept/reject/merge review path before the source artifact changes.
- **Intent-match review dispatch nudges** — requests that evaluate, accept, approve, reject, or decide on produced work ("approve the PR", "is this correct", "did it solve the right problem", "assess the dashboard") now get a deterministic intent-match check: the operator's actual problem and acceptance criteria before treating a green build as correctness, an explicit right-problem answer, the right/wrong decisions the artifact embeds named by owner, problem definition diagnosed before architecture, and a passes-on-intent-match vs. passes-only-on-runnability verdict.
- **Spec-before-the-machine dispatch nudges** — requests that want a capability the tool/model does not yet support ("the model can't do that yet", "wait until the API supports it", "no such tool") or that build on prior artifacts ("reuse our old drafts", "rearrange the existing documents") now get a deterministic spec-first check: write the capability spec (behavior, inputs including prior artifacts as editable context, the read-back/steer point, and the verification) as a durable tool-agnostic file before choosing tooling, do not treat "the tool can't do that yet" as a reason to leave the capability unspecified, design prior artifacts as editable composition material rather than a blank-page start, name the read-back/revise step, measure realization against the written intent rather than a shipped feature list, and state a spec-present vs. blocked-on-tooling-parity verdict.
- **Argus command authority** — the chat prompt now tells Argus where it is (the Visionary dashboard), its full agent roster with dispatch ids, and the artifact conventions; a new `DISPATCH_TASK: task_id | agent_id` action lets it put agents to work directly through the same dispatch path the UI uses (CREATE_TASK/MOVE_TASK still supported).
- **Efficiency-vs-amplification dispatch nudges** — requests whose stated win is efficiency or the removal of the human ("we can be more efficient", "reduce headcount", "fewer people", "do more with less", "replace the manual step", "save time") now get a deterministic value-axis check: name whether the win is efficiency-as-replacement or person-amplification, the human capacity being multiplied, and the rider's retained decision, plus the structure supplied, the amplified-outcome measurement, and a no-riderless-machine rule, before the efficiency claim is treated as the win.
- **Runtime-reach portability dispatch nudges** — requests that bind a workflow to a named runtime/vendor ("use Claude to browse…", "connect an OpenAI agent to our API"), or that carry swap/lock-in pressure ("keep it portable", "so we can swap the model", "vendor lock"), now get a deterministic reach-and-vendor-independence check: name the exact reach requirement (web/URL/connector/API/files/tool), which runtimes actually have that reach, design the brief so the same instructions replay on a second capable runtime without rewriting the workflow, avoid anchoring work in the vendor-branded agent layer (per Gartner, up to ~70% of companies are expected to walk away from vendor-built agents by 2028), record a fallback reach proof or the exact access gap, and state a portable-across-runtimes vs. runtime-bound verdict. Applies Jake Van Clief's cross-runtime brief replay lesson (video 49YDUZD2kSI; the Dubai case — a Claude brief that failed on a reach gap succeeded unchanged in ChatGPT). Reach/vendor-binding layer, distinct from portable-instruction-asset (owning the instruction asset), workflow-resilience (outage/quota/degradation), and source-runtime-value (source-code/import work).
- **AI-as-compiler pipeline dispatch nudges** — requests that repeat an AI generation workflow ("build a pipeline", "make it repeatable", "generate for each client/lead/record", "batch generate", "turn our prompt into a template") now get a deterministic compilation-pipeline check: name each part of the pipeline (fixed instruction; variable inputs/source files; role/persona/context slot; output schema/format; validation checks; retry/error policy; stored result path; human review threshold), separate fixed prompt text from changing task/client/source data, prefer a parseable schema downstream systems can consume, record model/provider/parameters/context so a rerun or model swap reproduces rather than drifts, add validation (schema parse, source-citation check, diff/test, or confidence threshold plus human review) before trusting output, escalate from chat to a skill/script/agent only once copy/paste repeats or evaluation matters, and state a reproducible-compilation-pipeline vs. one-off-prompt verdict. Applies Jake Van Clief's AI-is-the-new-compiler lesson (videos `RZ0AcCLVPFA`, `jjV1ckgPzI0`): the unit is a small compilation pipeline, not a magic prompt, and the failure it prevents is opaque prompt chains that never state what is fixed, what varies, what validates output, or where the result becomes durable state. Distinct from intent-compiler-workbench (folders as portable intent packages), program-decomposition (instructions + runner + surviving state), classifier-gate (bounded repeated judgment), and execution-evidence-gate (trusting a "running/successful" status). `src/ai-as-compiler-pipeline.js` holds the deterministic gate; this nudge makes the operator's agents actually run it at dispatch time.
- **Task artifacts** — every dispatch runs inside `~/Visionary/<project>/task-<id>`; runs record the workdir and every file produced (`agent_runs.workdir`, `artifacts_json`). Task detail shows a Runs & Artifacts panel with output, file list, Open Folder, and click-to-open files (`GET /api/runs/:id`, `POST /api/runs/:id/open` with realpath containment).
- **Cost capture (claude)** — the claude adapter dispatches with `--output-format json`; runs store real `input_tokens`/`output_tokens` and the harness's own `total_cost_usd` instead of estimates.
- **launchd lifecycle** — `ai.visionary.server` + `ai.visionary.watchdog` KeepAlive services; `vision start|stop|restart|status` drive launchd when installed (plain background process otherwise). New `vision restart`.

### Changed
- **Jarvis → Argus** — new identity (`personalities/agents/argus.md`), harness chain `hermes → claude-code → codex`; DB migration carries messages/health/tasks history to the new id.
- **Chat rides the failover engine** — `/api/chat` routes through `executeWithFailover` with read-only tools instead of a hardcoded `openclaw agent --local` call; Hermes adapter uses `-Q` quiet mode.
- **Reviewer rebuilt** — reviews run through the reviewer's harness chain with the run's artifact list as evidence and read-only tools; verdicts parse the structured first `APPROVE:`/`REJECT:` line (no more keyword-anywhere false verdicts); inconclusive reviews stay in Review for the operator; rejection redeploys go through the normal dispatch path (workdir + failover); max-retry tasks stay in Review instead of bouncing to todo.

### Fixed
- Director personality frontmatter (`director-intelligence`, `director-engineering`, `director-security`, `director-operations`) still named the retired `jarvis` identity in `reports_to` while the org chart uses `argus`; the four are corrected so `scripts/validate-org-chart.mjs` reports zero warnings.
- `bridge.py` heartbeat crash (`sqlite3.Connection` has no `lastrowid`).
- Chat `CREATE_TASK` parser no longer fires on the instruction template echoed back by harnesses; missing `project_id` in chat task-creation activity writes.
- `/api/runs/:id/open` rejects symlink escapes and executable bundles.
- `bridge.py` crashed at import on macOS's default Python 3.9 (PEP 604 `X | None` annotations are evaluated at runtime), so the inter-agent message bridge never started; annotations now use `typing.Optional`.
- The augmentation-means and vibe-coded-audit prompt blocks double-escaped their line breaks, so their bodies were emitted as literal `\n` text and rendered as one run-on line inside the assembled agent prompt; both now emit real newlines between their bullet points.

## [2.1.0] — 2026-06-10

### The working-core release: agents actually run

Dispatch any agent from the org chart and watch real CLI output stream back live, with automatic failover across harnesses. The whole surface is redesigned as a native macOS app, boards are project-scoped, and a `vision` terminal command launches everything.

### Added
- **Agent OS core** — 16-node org chart (CEO → 4 directors → 11 ICs) from `personalities/org-chart.json`, harness failover engine, independent watchdog, cron scheduler, retention cleanup, prompt guardrails, deep-research pipeline, per-harness model cookbook, Spaces → Projects hierarchy, per-agent dispatch drawer, per-agent token-bucket rate limiting, token-aware failover replay, watchdog auto-nudge (#14–#22, org-chart era).
- **Streamed dispatch through failover** — the UI dispatch path now runs `executeWithFailover` against each agent's harness chain and streams stdout/stderr over new SSE events (`agent:output`, `agent:harness`); the drawer renders output live with a failover-position indicator. Kill switch cancels without failing over.
- **Real harness healthchecks** — all 7 adapters (openclaw, claude, hermes, cursor, codex, gemini, ollama) probe the actual CLI; boot banner reports which harnesses are available.
- **Agent personalities in dispatch** — each run is prefixed with the agent's charter so agents act their role; headless `claude` runs with tool permissions granted and stdin closed.
- **Deterministic launch** — `scripts/ensure-native.js` self-heals the better-sqlite3 ABI on `npm start`/`npm run verify`; streaming/failover/cancellation integration tests added to the verify gate.
- **`vision` terminal command + installer** — `./install.sh` sets up deps and links `vision` onto PATH: open the dash, start/stop/status, Electron app, logs.
- **Python backend (frozen)** — FastAPI port phases 0–2 (read-only routes + SSE bus, dispatch + failover, comm fabric) on port 3344; development frozen, Node remains the shipping backend (#23–#26).

### Changed
- **Native macOS UI (Apple HIG)** — full redesign: SF system fonts, Apple system colors, light/dark/system themes, translucent toolbar + source-list sidebar with SVG icons, inspector-style chat panel and agent drawer, segmented controls, Spotlight-style ⌘K, new app icon. Zero external font loads.
- **Boards are project-scoped** — the global all-tasks board is gone; `#/board` opens your last-used project board and New Task always targets the current project.
- Org chart hides legacy registry rows; run summaries unwrap OpenClaw JSON envelopes into readable text.

### Fixed
- `cursor-agent` dispatch used a nonexistent `--message` flag (now `-p`).
- Headless `claude -p` stalled ~3s waiting on stdin.
- Live dispatches no longer fail on tool-permission prompts.
- PWA manifest/theme colors and stale ROADMAP/STATE/README corrected; dead macOS Swift shell removed.

## [2.0.0] — 2026-06-08

### Major release: extensibility, portability, mobile, and a full visual overhaul

Visionary v2 is a five-feature release plus a complete UI redesign. The dashboard is now installable as a PWA, usable on a phone, backup-portable, plug-in friendly for non-OpenClaw runtimes, and configurable from a settings tab — all under a new Memphis-pop brutalist look.

### Added
- **PWA support** (#1, #7) — `public/manifest.json` + `public/sw.js`. Installable from Chrome desktop and iOS Safari "Add to Home Screen". Network-first for `/api/*`, cache-first for the static shell, SSE bypassed so real-time updates keep working. Apple-touch-icon + theme-color meta wired up.
- **Mobile-responsive layout** (#2) — breakpoints at 480px and 768px. Kanban collapses to 1-column on phones and 2×2 on small tablets. Chat panel docks to a bottom sheet on phones and slides over content as an overlay on tablets. All tap targets ≥44px in the phone breakpoint.
- **SQLite export / import endpoints** (#3) — `GET /api/export` dumps all five tables as a timestamped JSON file; `POST /api/import` restores from the same shape inside a single transaction (idempotent INSERT OR REPLACE). New "Export Data" link in the header. Round-trip smoke test included.
- **Agent runtime adapter interface** (#4) — dispatch is no longer hardcoded to `openclaw`. New `src/runtimes/` registry with adapters for `openclaw`, `claude-code`, and `hermes`. Agents gain a `runtime` column via forward migration. OpenClaw behaviour is unchanged.
- **Settings panel** (#5) — new Settings tab. Configure port, workspace path, theme, and default runtime from the UI. Persisted in SQLite via `GET /api/settings` / `PUT /api/settings`. Theme changes apply immediately; port/workspace changes require a restart.
- **Hermes gateway monitoring** (#6) — overview now surfaces the Hermes agent gateway's health when an orchestrator is configured.
- **Memphis-pop brutalist redesign** (#13) — full `public/styles.css` rewrite. Deep-black base with electric pink / cyan / lime / orange / violet accents. Hard 4px-offset shadows (no blur), 3px white borders, Archivo Black UPPERCASE labels, Inter for body, IBM Plex Mono for data. Status-colored kanban column headers (butter / cyan / orange / lime), agent cards rotate shadow color by `nth-of-type`, lime-green pulse on the LIVE SSE badge.

### Infrastructure
- CI workflow (`.github/workflows/test.yml`) — `npm run verify` on every push and PR, against Node 20.x and 22.x.
- Dependabot config — weekly npm and monthly GitHub Actions updates.
- `SECURITY.md` — threat model and private vulnerability reporting workflow.
- `VERSION` file and `CHANGELOG.md` as canonical sources.

### Changed
- Electron major: `32.3.3` → kept on 32 with builder updated to `26.15.2` (`#11`, `#12`, `9a35892`).
- `actions/checkout` bumped to v6 (`#10`).
- README "Configuration" section now documents the runtime adapter system and Settings tab.

### Fixed
- Board card priority badges render as styled spans instead of literal "badge-red" text (`30257ce`).
- Slop cleanup — removed dead `priorityBadge` hoisting collision, unified `bridgePublishMessage` / `bridgePublish` onto one `bridgePost` helper, dropped three inner `require('node:http')` shadows, removed unused `aid_removed` local in `bridge.py` (`402d8b5`).

## [0.1.0] — 2026-06-08

### Initial public release

First public cut of Visionary — a local-first desktop mission control for multi-agent AI systems.

### Added
- Tiny Node.js server (`node:http`, no Express) on port 3333
- SQLite persistence via `better-sqlite3` (the only npm dependency), WAL mode
- Server-Sent Events for real-time dashboard updates
- Vanilla JS + CSS frontend (no build step)
- Electron 32 desktop shell
- Optional Python `bridge.py` for ecosystem integrations
- Five tables: `projects`, `tasks`, `agent_runs`, `notifications`, `activity_log`
- Kanban board with drag-and-drop, agent status cards, command bar (Cmd+K)
- Dispatch engine with kill switch and activity feed
- Notifications inbox + brief/audit/portfolio viewers
- `/personalities/` — six reusable agent character docs (SOUL, VISIONARY, AGENTS, IDENTITY, MISSION_CONTROL, TEAM) as a starting template
- Full `.planning/` directory documenting how the project was built (phases 1-5)
- 14-test smoke suite (`tests/smoke.mjs`)
- MIT license, README, CONTRIBUTING, issue templates

### Configuration
- `VISIONARY_WORKSPACE` (default: `$HOME/.openclaw/workspace`)
- `VISIONARY_NODE` (default: current node binary)
- `PORT` (default: `3333`)
